01Architecture Overview

ทั้งโปรเจกต์เป็น Next.js App Router โมโนลิธตัวเดียว — ไม่มี backend แยก app/admin (หน้า UI ที่แอดมินเปิดใช้) กับ app/api (ทุก endpoint) อยู่ deploy เดียวกัน คุยกันผ่าน HTTP ภายใน origin เดียวกันเอง

LINE Platformwebhook / push / content API
↔ HTTPS ↔
Next.js Appapp/api/* route handlers
↔ SQL ↔
Postgresconversations, messages
↑ ↓
Admin Console (React)app/admin — TanStack Query cache
← SSE (poll ทุก 500ms) + axios ←→
app/api/events/*, app/api/conversations/*, app/api/messages/*

LINE เป็นฝ่าย push event เข้ามาทาง webhook เท่านั้น (เราไม่ได้ pull) — ทุกอย่างอื่น (ส่งข้อความ, ดึงรูป, sync read status) เราเป็นฝ่ายเรียกออกไปเอง

เส้นทางข้อความเข้า (LINE → admin): LINE ยิง webhook → app/api/webhook/route.ts ตรวจ signature → เขียนลง Postgres ผ่าน lib/db.ts → admin เห็นข้อความใหม่เพราะ app/api/events/messages poll DB ทุก 500ms แล้วส่งผ่าน SSE เข้า TanStack Query cache ของหน้า admin

เส้นทางข้อความออก (admin → LINE): แอดมินพิมพ์ → optimistic bubble โผล่ทันที (client-only) → app/api/messages/send เรียก lib/line.ts (Push API) → ถ้าสำเร็จค่อยบันทึกลง Postgres → bubble ปลอมถูกสลับเป็นแถวจริงจาก server

ทำไมไม่ใช้ WebSocket จริง: Vercel serverless function มี maxDuration จำกัด เปิด connection ค้างไว้ตลอดแบบ WebSocket ทำไม่ได้ตรงๆ โดยไม่พึ่ง infra เพิ่ม (Ably/Redis) — เลือกใช้ SSE ที่ปิดตัวเองทุก ~50 วิ + browser's EventSource reconnect ให้ฟรีแทน

ทำไม channel access token ไม่หลุดไปฝั่ง client: ทุกจุดที่ต้องใช้ token (push ข้อความ, ดึงรูปภาพ, sync read status) รวมอยู่ใน lib/line.ts เท่านั้น เรียกได้จากฝั่ง server (API routes) เท่านั้น — browser ไม่มีทางเห็น token เลย
